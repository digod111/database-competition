## 哈希表的基本结构

哈希表通过哈希函数把关键字映射到桶数组的下标。理想情况下一次查找就能定位，平均时间复杂度 O(1)。但不同关键字可能映射到同一个下标，这就是哈希冲突。

哈希函数应尽量均匀分布，并利用关键字中所有有区分度的信息。桶的数量通常取质数或 2 的幂，具体取决于冲突处理方式和取模/位运算策略。

## 链地址法

链地址法把每个桶实现为一个链表（或红黑树），所有映射到同一桶的元素都挂在该桶下。

- 优点：实现简单；负载因子可以大于 1；删除操作直接摘链即可。
- 缺点：需要额外的指针空间；链表节点分散，缓存局部性较差。
- Java 的 HashMap 在链表长度超过阈值且容量足够时会转成红黑树，降低极端冲突下的查找成本。

## 开放定址法

开放定址法不建链表，发生冲突时按照探测序列在表内寻找下一个空位。

- 线性探测：依次检查下一个位置，容易产生一次聚集。
- 二次探测：按平方步长跳跃，减少聚集，但可能探测不到所有空位。
- 双重哈希：用第二个哈希函数决定步长，分布更均匀。
- 删除不能直接把槽位置空，否则会截断探测链，通常使用墓碑标记。

开放定址法的负载因子必须小于 1；负载因子越高，探测长度增长越快。

## 负载因子与扩容

负载因子 = 已存元素数 / 桶数量。它衡量哈希表的拥挤程度。

- 负载因子过高：冲突概率上升，平均查找长度变长。
- 负载因子过低：空间浪费。
- 常见做法是设置阈值（例如 0.75），超过后扩容并重新哈希所有元素。
- 扩容的代价是 O(n)，但摊还到每次插入仍是常数级。
