## DNS 解析过程

DNS 把域名解析为 IP 地址。一次典型解析会经过浏览器缓存、操作系统缓存、本地 DNS 服务器，再向上查询。

- 递归查询：客户端把请求交给本地 DNS 服务器，由它负责最终返回结果；客户端只发一次请求。
- 迭代查询：本地 DNS 服务器依次向根域名服务器、顶级域名服务器、权威域名服务器查询，每一级返回下一级地址，直到拿到结果。
- 根服务器不直接保存具体域名的 A 记录，而是告诉解析器去哪个顶级域服务器继续查。
- 常见记录类型：A（IPv4 地址）、AAAA（IPv6 地址）、CNAME（别名）、MX（邮件交换）、NS（域名服务器）。
- 解析结果会按 TTL 缓存；TTL 过长会导致变更生效慢，过短会增加查询压力。
- DNS 通常使用 UDP 53 端口；响应过大、区域传送等场景使用 TCP。

## HTTPS 与 TLS

HTTPS 是 HTTP over TLS，在 HTTP 和 TCP 之间增加 TLS 层，提供机密性、完整性和身份认证。

- 握手阶段使用非对称加密（或密钥交换算法）协商出会话密钥，并用证书验证服务器身份。
- 数据传输阶段使用对称加密，因为对称加密速度快，适合大量数据。
- 证书由受信任的 CA 签发，浏览器通过证书链和根证书验证服务器身份，防止中间人攻击。
- 证书中包含域名、公钥、有效期和签名等信息；域名不匹配或证书过期都会导致浏览器告警。
- TLS 还通过 MAC 或 AEAD 算法保证数据完整性，防止报文被篡改。

HTTPS 不能简单理解为“把 HTTP 内容用非对称加密包起来”：实际是先用非对称机制安全地协商对称密钥，再用对称密钥加密应用数据。
