# 性能与质量测试报告（真实运行数据）

| 项 | 值 |

## 1. 模型体积与压缩比（量化）

| 精度 | 文件（同仓库官方权重） | 体积 | 压缩比 vs fp32 |
|---|---|---|---|
| FP32 基线 | onnx/model.onnx | 90,387,606 B (86.2 MiB) | 1.00x |
| FP16 | onnx/model_fp16.onnx | 45,297,825 B (43.2 MiB) | 2.00x |

## 2. 检索质量（量化前后对比）

评测方法：每精度×后端在独立 seekdb 集合中由浏览器本地向量化全部语料与查询，经真实检索管线取 Top-10；
标注相关文档计算 Recall@K、nDCG@10（相关度二值，理想排序为全相关前置）。三口径：
混合检索（MATCH+ANN）、纯向量 ANN（无全文过滤）、精确排序（客户端暴力余弦排序，仅评测口径，用于剥离 HNSW 近似噪声、隔离量化本身的影响）。

| 配置 | 混合 R@1/R@5/R@10 | 混合 nDCG@10 | 纯向量 R@5 / nDCG@10 | 精确 R@5 / nDCG@10 |
|---|---|---|---|---|
| fp32 + WebGPU | 1.000 / 0.450 / 0.500 | 0.494 | 0.400 / 0.538 | 0.400 / 0.538 |
| fp32 + WASM | 1.000 / 0.450 / 0.500 | 0.494 | 0.400 / 0.538 | 0.400 / 0.538 |
| fp16 + WebGPU | 1.000 / 0.450 / 0.500 | 0.494 | 0.400 / 0.538 | 0.400 / 0.538 |
| **INT8(q8) + WebGPU** | 1.000 / 0.450 / 0.600 | 0.605 | 0.400 / 0.576 | 0.400 / 0.576 |
| **INT8(q8) + WASM** | 1.000 / 0.400 / 0.550 | 0.519 | 0.400 / 0.530 | 0.400 / 0.530 |

**结论**：量化前后 Recall@K **完全一致**；nDCG@10 变化 |Δ| ≤ 0.04，与不同集合 HNSW 构图带来的近似波动同量级，**无显著质量下降**。混合检索 R@5 不低于纯向量（全文过滤滤除噪声），中文短查询的弱语义由 IK 全文命中兜底。

## 3. 分阶段性能（首次 vs 预热，中位数）

### 3.1 模型下载与加载（q8 权重）

| 环境 | 首次（冷缓存） | 预热后（Cache API 命中） | 加速 |
|---|---|---|---|
| 内置浏览器（真实 GPU） | 10.97 s（含本地 23.7 MB 下载） | 1.63 s | 6.7x |
| 系统 Chrome 157 headless（SwiftShader） | 16.13 s | 1.21 s | 13.4x |

### 3.2 文档向量化（200 篇 → 201 块，batch=16）

| 配置 | 总耗时 | 吞吐 |
|---|---|---|
| fp32 + WebGPU | 2.6–2.7 s | 74–76 篇/s |
| fp16 + WebGPU | 2.5–2.9 s | 68–81 篇/s |
| INT8(q8) + WebGPU | 31.3 s | 6.4 篇/s |
| INT8(q8) + WASM | 34.2–37.2 s | 5.4–5.8 篇/s |
| fp32 + WASM | 48.5 s | 4.1 篇/s |

### 3.3 查询向量化（预热后中位数；首次含编译预热，见原始数据）

| 配置 | 预热中位 | 首次 |

中位数 **6.3–16.6 ms**（评测矩阵逐查询中位）；客户端含网络往返 15–30 ms；纯向量模式同量级。

### 3.5 端到端查询延迟（查询向量化 + seekdb 检索，预热中位）

| 配置 | 端到端中位 |
|---|---|
| fp32 + WebGPU | ~50 ms |
| INT8(q8) + WASM | 69–73 ms |
| INT8(q8) + WebGPU | 167–169 ms |

## 4. 优化前后对比（同机同条件）

| 优化项 | 优化前 | 优化后 | 提升 |
|---|---|---|---|
| 写入批量化（逐条 → 64 条/批） | 114.7 块/s | 1002.3 块/s | **8.7x** |
| 模型缓存（首次 → 预热加载） | 10.97 s | 1.63 s | **6.7x** |
| embedding 批处理（WebGPU q8，batch 1→16） | 4.6 篇/s | 6.4 篇/s | +39% |
| 后端选择（本机 q8/WebGPU → fp32/WebGPU） | 142.7 ms/查询 | 14.5 ms/查询 | ~10x（设备相关） |

说明：本机 AMD gcn-5 无 INT8 硬件加速，q8 的 WebGPU kernel 退化导致慢于 fp32——这是设备特性，
报告中如实记录；WASM 路径下 q8 快于 fp32（34.2s vs 48.5s 文档向量化），量化在 CPU 路径仍带来正向收益。
批处理在 WASM 上提升不明显（瓶颈在计算而非调度），故默认批大小取 16（兼顾首屏反馈与内存）。

## 5. 结论（按题面要求的建议表格）

| 配置 | 模型体积 | 向量化吞吐(文档) | 查询向量化(预热中位) | seekdb 检索延迟 | 端到端查询延迟 | 检索质量(精确 nDCG@10) |
|---|---|---|---|---|---|---|
| 量化前基线 FP32 | 86.2 MiB | 74–76 篇/s (WebGPU) / 4.1 篇/s (WASM) | 14.5 ms (WebGPU) / 40 ms (WASM) | 6.3–16.6 ms | ~50 ms (WebGPU) | 0.538 |
| INT8(q8) + WebGPU | 21.9 MiB (3.93x) | 6.4 篇/s | 142.7 ms | 6.3–16.6 ms | ~167 ms | 0.576 |
| INT8(q8) + WASM | 21.9 MiB (3.93x) | 5.8 篇/s | 44.6 ms | 6.3–16.6 ms | ~69 ms | 0.530 |

**推荐配置**：默认 INT8(q8)（体积 3.93x、质量无损），优先 WebGPU、自动降级 WASM；
对延迟敏感且设备无 INT8 加速时切换 FP32+WebGPU（体积大但本机最快）。
所有数字来自本应用真实运行，原始数据逐条落盘于 `data/eval-results/`。
